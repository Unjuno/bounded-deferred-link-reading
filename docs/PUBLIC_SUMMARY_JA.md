# 公開向け要約 — 2026-08-27

## 何を調べていたか

最初の問いは単純でした。

**分からないリンクや概念が出たとき、すぐに調べるべきか、それとも一旦そのまま読み進めるべきか。**

計算実験を重ねると、かなり一貫したパターンが出ました。

- 分からないものを全部その場で解決するのは非効率になりやすい。
- 一旦読み進めると、文脈だけで自然に解決するものがある。
- 重要でなかったことが後から分かるものもある。
- 本当に重要なものは、後続内容がその概念に依存し始めると価値が上がる。
- その時点で問い合わせる方がよい。

したがって中心原理は、

> **未知は出現した瞬間に解決するのではなく、解決価値が保留価値を上回った時点で解決する。**

になりました。

## ハイパーリンクからチャットへ

この構造はリンクだけではなく、チャットでの質問にもそのまま拡張できます。

LMの回答には新しい分からない語や概念が出てきます。しかし、それを全部すぐ再質問すると深掘りが止まらなくなります。

そこで、回答中の新しい疑問を一旦frontierに戻し、本文や本来の作業を続け、重要になったものだけを後から聞く方がよい。

実験では、質問単体の即時価値より、その質問から先に得られる**recursive subtree value**を予測した方策が複数環境で優位でした。

## 解析的に見ると

完全な問い合わせ木が分かっている場合、この問題はprecedence-constrained tree knapsackとして動的計画法でexactに解けます。

つまり研究の後半では、「良いheuristicを探す」より、

> **解析的oracleを、限られた観測・記憶・時間でどこまで近似できるか**

が本質的な問題だと分かってきました。

## UIへの含意

ここから、かなり直接的に新しい読書/チャットUIの形も導けます。

読者自身に「何が重要か」を全部判断させる必要はありません。

AIが、後の内容に強く依存しそうな語句を太字・下線・マーカーなどで控えめに強調する。そして、クリックすればすぐ質問できる。

ただし、強調したものを全部自動で説明するのではなく、

- 重要候補として保留する
- 後続文脈で自然解決したら消す
- 後で重要度が上がったら上位へ出す
- 本当に必要になった時だけ説明する

という方が理論に合います。

将来の形は、単純な一本道チャットより、

**本文 + AI重要度表示 + 保留質問frontier + チャット**

に近いと考えています。

## 現時点の境界

これはまだ「人間の最適な読書法を証明した」という研究ではありません。

計算・ナビゲーション・自然言語代理タスクではかなり一貫した構造が見えていますが、人間の理解度、記憶、疲労、割り込みコストについては直接検証が必要です。

したがって現在の主張は、

> **defer-vs-resolveという数理構造が、ハイパーテキスト、再帰問い合わせ、そして将来のチャットUIを一つの枠組みで説明できる**

というところまでです。

## X投稿用短文案

「分からないことは、すぐ全部調べるべきか？」を実験していたら、だいぶ数理構造が見えてきた。

結論は、未知を見つけた瞬間に解決するのではなく、まず読み進める。文脈で自然解決するものは放置し、それでも後の理解に重要になったものだけを聞く。

さらにLM回答中の新しい疑問も即深掘りせず、一旦frontierに戻す方がいい。

この問題、完全な問い合わせ木が分かっていればtree knapsack / Bellman DPでかなり解析的に解ける。

で、面白いのはUIの方。読者自身に重要度判定を全部やらせず、AIが重要そうな語を太字等で示し、質問候補として保留し、必要になった時だけチャットで説明する形が自然に出てくる。

未来の読書UIは「本文 + AI重要度表示 + 保留質問frontier + チャット」になるのかもしれない。
